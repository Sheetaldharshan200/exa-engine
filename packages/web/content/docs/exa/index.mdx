[**Exa**](./index.mdx) is the AI agent built for your data. It talks to your Exasol databases natively, runs models locally or in the cloud, and comes as two doors into one product: `exa` in the terminal, and `exa web` — the full Exasol Studio in your browser.

Let's get started. (Looking for the app itself? The **[Exasol Studio docs](../studio/index.mdx)** are the second tab of this site.)

---

#### Prerequisites

To use Exa in your terminal, you'll need:

1. A modern terminal emulator like:
   - [WezTerm](https://wezterm.org), cross-platform
   - [Alacritty](https://alacritty.org), cross-platform
   - [Ghostty](https://ghostty.org), Linux and macOS
   - [Kitty](https://sw.kovidgoyal.net/kitty/), Linux and macOS

2. A model: an API key for a cloud provider, a GitHub Copilot account, or none at all — Exa can [run models on your machine](./data/local-models.mdx).

## Install

The easiest way to install Exa is through the install script.

```bash
curl -fsSL https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/install.sh | bash
```

On Windows, in PowerShell:

```powershell
irm https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/install.ps1 | iex
```

You can also install it with a Node.js package manager:

<Tabs items={["npm", "Bun", "pnpm", "Yarn"]}>

  <Tab value="npm">
  ```bash
  npm install -g exa-ai
  ```
  </Tab>

  <Tab value="Bun">
  ```bash
  bun install -g exa-ai
  ```
  </Tab>

  <Tab value="pnpm">
  ```bash
  pnpm add -g exa-ai
  ```
  </Tab>

  <Tab value="Yarn">
  ```bash
  yarn global add exa-ai
  ```
  </Tab>

</Tabs>

Or grab a binary from the [Releases](https://github.com/Sheetaldharshan200/exa-engine/releases) page.

<Callout type="info" title="Windows">
For the best experience on Windows, we recommend [Windows Subsystem for Linux (WSL)](./reference/windows-wsl.mdx) — the native build works, but WSL gets full feature parity.
</Callout>

## Configure

Exa works with any LLM provider. Run the `/connect` command in the TUI and pick one:

```txt
/connect
```

- **GitHub Copilot** — sign in with GitHub and use your Copilot account's models. No API key.
- **Anthropic, OpenAI, Google, and 75+ others** — paste the provider's API key when prompted.
- **Exa engine (local)** — pick a curated model and Exa downloads and serves it on your machine. No account at all.
- **Ollama** — if it is running locally, its models are already in the list.

[Learn more about providers](./configure/providers.mdx#directory) and [local models](./data/local-models.mdx).

## Connect your data

Exa's difference is what happens next: connect a database.

```bash
exa connect
```

With no arguments it finds what is already running — or installs Exasol Personal locally in one step. Connect several databases and query them all from one session; see [Databases](./data/databases.mdx).

In the TUI, `/connect-db` lists what is connected and switches the default.

## Initialize

Now that you've configured a provider, you can navigate to a folder that
you want to work on.

```bash
cd /path/to/project
```

And run Exa.

```bash
exa
```

Next, initialize Exa for the folder by running the following command.

```bash
/init
```

This will get Exa to analyze your folder and create an `AGENTS.md` file in
the folder root.

<Callout type="info">
You should commit your folder's `AGENTS.md` file to Git.
</Callout>

This helps Exa understand the folder structure and the coding patterns
used.

## Usage

You are now ready to use Exa to work on your folder. Feel free to ask it
anything!

If you are new to using an AI coding agent, here are some examples that might
help.

---

### Ask questions

You can ask Exa to explain the codebase to you.

<Callout type="info">
Use the `@` key to fuzzy search for files in the folder.
</Callout>

```txt
How is authentication handled in @packages/functions/src/api/index.ts
```

This is helpful if there's a part of the codebase that you didn't work on.

---

### Add features

You can ask Exa to add new features to your folder. Though we first recommend asking it to create a plan.

1. **Create a plan**

   Exa has a _Plan mode_ that disables its ability to make changes and
   instead suggest _how_ it'll implement the feature.

   Switch to it using the **Tab** key. You'll see an indicator for this in the lower right corner.

   ```bash title="Switch
   <TAB>
   ```

   Now let's describe what we want it to do.

   ```txt
   When a user deletes a note, we'd like to flag it as deleted in the database.
   Then create a screen that shows all the recently deleted notes.
   From this screen, the user can undelete a note or permanently delete it.
   ```

   You want to give Exa enough details to understand what you want. It helps
   to talk to it like you are talking to a junior developer on your team.

   <Callout type="info">
   Give Exa plenty of context and examples to help it understand what you
   want.
   </Callout>

2. **Iterate on the plan**

   Once it gives you a plan, you can give it feedback or add more details.

   ```txt
   We'd like to design this new screen using a design I've used before.
   [Image #1] Take a look at this image and use it as a reference.
   ```

   <Callout type="info">
   Drag and drop images into the terminal to add them to the prompt.
   </Callout>

   Exa can scan any images you give it and add them to the prompt. You can
   do this by dragging and dropping an image into the terminal.

3. **Build the feature**

   Once you feel comfortable with the plan, switch back to _Build mode_ by
   hitting the **Tab** key again.

   ```bash
   <TAB>
   ```

   And asking it to make the changes.

   ```bash
   Sounds good! Go ahead and make the changes.
   ```

---

### Make changes

For more straightforward changes, you can ask Exa to directly build it
without having to review the plan first.

```txt
We need to add authentication to the /settings route. Take a look at how this is
handled in the /notes route in @packages/functions/src/notes.ts and implement
the same logic in @packages/functions/src/settings.ts
```

You want to make sure you provide a good amount of detail so Exa makes the right
changes.

---

### Undo changes

Let's say you ask Exa to make some changes.

```txt
Can you refactor the function in @packages/functions/src/api/index.ts?
```

But you realize that it is not what you wanted. You **can undo** the changes
using the `/undo` command.

```bash
/undo
```

Exa will now revert the changes you made and show your original message
again.

```txt
Can you refactor the function in @packages/functions/src/api/index.ts?
```

From here you can tweak the prompt and ask Exa to try again.

<Callout type="info">
You can run `/undo` multiple times to undo multiple changes.
</Callout>

Or you **can redo** the changes using the `/redo` command.

```bash
/redo
```

## Use the browser instead

Everything above works in the browser too. Start the web app and open the printed URL:

```bash
exa web
```

This serves the full Exasol Studio — your connections, schemas, query editor, and dashboards — backed by the same engine as the TUI. Set `EXA_SERVER_PASSWORD` before exposing it beyond your machine. [Learn more](./usage/web.mdx).
