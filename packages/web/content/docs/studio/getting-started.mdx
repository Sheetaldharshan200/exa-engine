## Desktop app

Download the build for your platform from the [releases page](https://github.com/Sheetaldharshan200/Exasol-studio/releases) — macOS (dmg), Windows (exe/msi), and Linux (AppImage/deb/rpm).

First run walks you through, in order:

1. **A master password** — Studio's vault, protecting secrets at rest. Save the five recovery codes it shows once (copy or download); see [Security](./security.mdx).
2. **A starter kit** — pick a curated pack (Local AI Stack, Student, Data Explorer, Data Scientist, AI/Agent Builder) or skip; the core stack (local database, PyExasol, ExaPump, MCP server, agent skills) installs regardless.
3. **A short guided tour** — five spotlight steps over the activity bar, connecting, query tabs, the visualizer, and the assistant.

For the database itself: connect an existing Exasol, or let Studio install **Exasol Personal** locally — a full Exasol database on your machine, managed from the Marketplace, no configuration.

When Personal is your only database, Studio connects to it automatically on launch — zero-setup. The moment you add your own connections, nothing connects without a click.

## The local web app

Studio is also a **local web app** — the exa engine ships the exact same application and serves it in your browser. Install the engine once:

```bash
# one-line installer
curl -fsSL https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/install.sh | bash

# or via npm
npm install -g exa-ai
```

Then:

```bash
exa web
```

Your browser opens Studio at `http://127.0.0.1:4096` — the app's own unlock screen asks for your master password once (the same vault as the desktop app), and you work against the same shared connections. The server runs until you stop it (`Ctrl+C`) — after a reboot, just run `exa web` again.

A few desktop-only abilities (managing the local database's lifecycle, filesystem access, native terminals) are named as such in the UI rather than failing silently — a CLI-installed Exasol Personal still shows up connected and running.

## Staying current

Studio's runtime pieces — the exa engine, Exasol Personal, ExaPump — update from their source repositories' releases through **Managed Components** in the Marketplace. Nothing is pinned; every install resolves the latest release, digest-verified.
