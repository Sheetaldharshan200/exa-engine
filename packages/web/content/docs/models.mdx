Exa uses the [AI SDK](https://ai-sdk.dev/) and [Models.dev](https://models.dev) to support **75+ LLM providers** and it supports running local models.

---

## Providers

Most popular providers are preloaded by default. If you've added the credentials for a provider through the `/connect` command, they'll be available when you start Exa.

Learn more about [providers](./providers.mdx).

---

## Select a model

Once you've configured your provider you can select the model you want by typing in:

```bash
/models
```

## Set a default

To set one of these as the default model, you can set the `model` key in your
Exa config.

```json title="exa.json"
{
  "$schema": "https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/schema/config.json",
  "model": "lmstudio/google/gemma-3n-e4b"
}
```

Here the full ID is `provider_id/model_id`. For example, with Anthropic you would use `anthropic/claude-sonnet-5`.

If you've configured a [custom provider](./providers.mdx#custom), the `provider_id` is key from the `provider` part of your config, and the `model_id` is the key from `provider.models`.

## Configure models

You can globally configure a model's options through the config.

```jsonc title="exa.jsonc"
{
  "$schema": "https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/schema/config.json",
  "provider": {
    "openai": {
      "models": {
        "gpt-5": {
          "options": {
            "reasoningEffort": "high",
            "textVerbosity": "low",
            "reasoningSummary": "auto",
            "include": ["reasoning.encrypted_content"],
          },
        },
      },
    },
    "anthropic": {
      "models": {
        "claude-sonnet-4-5-20250929": {
          "options": {
            "thinking": {
              "type": "enabled",
              "budgetTokens": 16000,
            },
          },
        },
      },
    },
  },
}
```

Here we're configuring global settings for two built-in models: `gpt-5` when accessed via the `openai` provider, and `claude-sonnet-4-20250514` when accessed via the `anthropic` provider.
The built-in provider and model names can be found on [Models.dev](https://models.dev).

You can also configure these options for any agents that you are using. The agent config overrides any global options here. [Learn more](./agents.mdx#additional).

You can also define custom variants that extend built-in ones. Variants let you configure different settings for the same model without creating duplicate entries:

```jsonc title="exa.jsonc"
{
  "$schema": "https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/schema/config.json",
  "provider": {
    "exa": {
      "models": {
        "gpt-5": {
          "variants": {
            "high": {
              "reasoningEffort": "high",
              "textVerbosity": "low",
              "reasoningSummary": "auto",
            },
            "low": {
              "reasoningEffort": "low",
              "textVerbosity": "low",
              "reasoningSummary": "auto",
            },
          },
        },
      },
    },
  },
}
```

## Variants

Many models support multiple variants with different configurations. Exa ships with built-in default variants for popular providers.

### Built-in variants

Exa ships with default variants for many providers:

**Anthropic**:

- `high` - High thinking budget (default)
- `max` - Maximum thinking budget

**OpenAI**:

Varies by model but roughly:

- `none` - No reasoning
- `minimal` - Minimal reasoning effort
- `low` - Low reasoning effort
- `medium` - Medium reasoning effort
- `high` - High reasoning effort
- `xhigh` - Extra high reasoning effort

**Google**:

- `low` - Lower effort/token budget
- `high` - Higher effort/token budget

<Callout type="info">
This list is not comprehensive. Many other providers have built-in defaults too.
</Callout>

### Custom variants

You can override existing variants or add your own:

```jsonc title="exa.jsonc"
{
  "$schema": "https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/schema/config.json",
  "provider": {
    "openai": {
      "models": {
        "gpt-5": {
          "variants": {
            "thinking": {
              "reasoningEffort": "high",
              "textVerbosity": "low",
            },
            "fast": {
              "disabled": true,
            },
          },
        },
      },
    },
  },
}
```

### Cycle variants

Use the keybind `variant_cycle` to quickly switch between variants. [Learn more](./keybinds.mdx).

## Switching fast

The `/models` picker is interactive; for one-command switching, define an agent per setup you use. Any `.md` file in `.exa/agent/` becomes a `/name` command:

```markdown title=".exa/agent/sonnet-high.md"
---
model: anthropic/claude-sonnet-4-5
variant: high
---
```

Now `/sonnet-high` switches model and reasoning effort in one keystroke sequence — no menus. Frontmatter-only files keep the default prompt and change only what they name; see [Agents](./agents.mdx) and [Variants](#variants).

Multiple accounts on the same provider (two Claude subscriptions, work and personal ChatGPT) are managed with [`exa accounts`](./cli.mdx#accounts).

## Loading models

When Exa starts up, it checks for models in the following priority order:

1. The `--model` or `-m` command line flag. The format is the same as in the config file: `provider_id/model_id`.

2. The model list in the Exa config.

   ```json title="exa.json"
   {
     "$schema": "https://raw.githubusercontent.com/Sheetaldharshan200/exa-engine/main/schema/config.json",
     "model": "anthropic/claude-sonnet-4-20250514"
   }
   ```

   The format here is `provider/model`.

3. The last used model.

4. The first model using an internal priority.
